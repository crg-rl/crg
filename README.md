# Continual Reasoning Gym

This is the anonymous code supplement for an ICLR 2027 submission. Continual
Reasoning Gym (CRG) is a reusable continual-RLVR training and evaluation
environment. It provides ordered task streams, stage-wise policy training,
all-task evaluation, continual-learning baselines, and Continual Prompt Replay
(CPR).

## Included components

- `mllm-crl/`: task streams, rewards, vanilla sequential/MTRL launchers, and
  evaluation utilities.
- `continual-rlvr-algorithms/`: EWC, FIRE, KL regularization, Muon, OSFT,
  ReDo, CPR, and the stale-trajectory/sample-replay ablation.
- VERL is an external dependency pinned to an upstream commit. This archive
  does not include its source.
- `tests/`: lightweight metric tests.

## Task streams

The launchers cover five 500-update streams:

1. Reasoning Gym algorithmic (10 ordered tasks, 50 updates per task)
2. Reasoning Gym algebra (6 ordered tasks, 84 updates per task; training stops
   at update 500)
3. VisuLogic quantitative (4 ordered stages, 125 updates per stage)
4. VisuLogic spatial (6 ordered stages, 84 updates per stage; training stops at
   update 500)
5. VisuLogic positional (4 ordered stages, 125 updates per stage)

CPR launchers use `replay_scope=previous_tasks`. Stored prompts retain their
task/verifier metadata, while responses are regenerated by the current policy.
The implementation also supports `replay_scope=all_seen` as an explicit
ablation override.

The sample-replay ablation is opt-in. It stores each historical response with
its sequence tensors and behavior-policy log probabilities, injects the stored
trajectory only for replay-labelled rows, recomputes verifier rewards and GRPO
advantages, and uses explicit rollout importance sampling. Its default flag is
`off_policy=false`; the dedicated ablation launcher sets `off_policy=true`.

## Environment

The training stack targets Python 3.11 and the following tested family of
packages:

- PyTorch 2.7.x
- VERL 0.8.0.dev at commit `adff7956cefd8ef707cd67dd8e08c06fa63679bd`
- vLLM 0.11.x
- reasoning-gym 0.1.24
- Hydra 1.3.x

Install accelerator-specific PyTorch and vLLM wheels for the target hardware.

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -U pip
git clone https://github.com/verl-project/verl.git ../verl
git -C ../verl checkout --detach adff7956cefd8ef707cd67dd8e08c06fa63679bd
git -C ../verl apply "$PWD/patches/verl-crg-runtime.patch"
pip install -e ../verl
pip install -e ./mllm-crl
pip install -e ./continual-rlvr-algorithms
export VERL_SOURCE_ROOT="$(cd ../verl && pwd)"
export VERL_CONFIG_ROOT="$(python scripts/locate_verl_config.py)"
```

## Data and model paths

The text streams are generated through `reasoning-gym`. The visual streams use
public VisuLogic data with project-defined ordered subtype labels. VLM launchers
expect `train.parquet` and `val.parquet` under the path selected by
`VISULOGIC_DATA_ROOT`. Each record must provide the fields consumed by
`mllm_crl.task.visulogic.crl_dataset`, including the stage label in
`extra_info.subcategory`.

Default model identifiers are public Hugging Face identifiers. Override them
with a local path when needed:

```bash
export MODEL_PATH=/path/to/local/model
export VISULOGIC_DATA_ROOT=/path/to/domain/vanilla_crl
export N_GPU=8
export N_CPU=128
```

Official VisuLogic resources:

- Dataset: <https://huggingface.co/datasets/VisuLogic/VisuLogic>
- Training data: <https://huggingface.co/datasets/VisuLogic/VisuLogic-Train>
- Evaluation code: <https://github.com/VisuLogic-Benchmark/VisuLogic-Eval>

## Example launches

Run commands from an experiment-output directory outside the source tree.

```bash
# Vanilla sequential RLVR: algorithmic stream
bash ../mllm-crl/example_scripts/reasoning_gym/crl_tasks_algorithmic_qwen3_4b_grpo_fsdp_vllm_910b.sh

# CPR: algorithmic stream
bash ../continual-rlvr-algorithms/example_scripts/reasoning_gym/algorithmic/crl_tasks_prompt_replay_qwen3_4b_grpo_fsdp_vllm_910b.sh

# CPR: quantitative visual stream
bash ../continual-rlvr-algorithms/example_scripts/visulogic/crl/crl_tasks_visulogic_quantitative_reasoning_prompt_replay_qwen2_5vl_7b_grpo_fsdp_vllm.sh

# Sample replay (stale trajectories): algorithmic stream ablation
bash ../continual-rlvr-algorithms/example_scripts/reasoning_gym/algorithmic/ablations/crl_tasks_stale_trajectory_replay_qwen3_4b_grpo_fsdp_vllm.sh
```

The scripts use local console/TensorBoard logging by default.

## Evaluation

`mllm-crl/evaluation/` contains:

- `evaluation.crl_metric`: matrix materialization and CRL metrics
- `evaluation.base_ability`: text ability evaluation wrapper
- `evaluation.vlm_general_ability`: VLM ability evaluation wrapper
- `evaluation.entropy_metric`: generated-token entropy diagnostics

The CRL metric input uses `performance_matrix[row][column]` for the checkpoint
after stage `row` evaluated on task `column`.

## Verification

Run the metric unit tests from the extracted archive root:

```bash
python3 -m unittest tests.test_crl_metrics -v
```

After installing the full training stack, run the tensor-level sample-replay
contract check:

```bash
PYTHONPATH="$PWD/continual-rlvr-algorithms" \
  python validation/test_stale_trajectory_contract.py
```
